# Local audio-environment model bake-off

Updated: 2026-06-29 21:30 America/New_York

## Objective

Build effective, stable, low-latency understanding of the real audio environment on one DGX Spark. Lane-to-lane dialog is a controllable self-test generator, not the objective. Evaluation therefore covers speech fidelity, non-speech understanding, semantic response quality, tool-choice correctness, robustness across repeated acoustic passes, and end-to-end reaction time.

## Non-negotiable controls

- All evaluated inference is local to the DGX Spark.
- Cross-lane test information travels through physical speaker-to-air-to-microphone audio only.
- Reference text is used only by the scorer after inference. It is never placed in model prompts.
- No phrase-specific correction, deterministic intent matcher, transcript handoff, or hidden lane context.
- Physical loudness and all playback/capture gain values are frozen at the values supplied by the user.
- Each model receives the same preserved raw WAV for comparable offline trials. Live physical trials follow for finalists.

## Hardware and live baseline

- NVIDIA GB10 (Blackwell), aarch64 Linux, 121 GiB unified system memory.
- At the start of this bake-off, only about 3 GiB was available because the live multimodal vLLM service reserved most unified memory. Large-model trials therefore require a controlled stop/benchmark/restore cycle; this is recorded separately from inference latency.
- Live recognizer: `nemotron_3_nano_omni` through local vLLM.
- Fixed speech gates: RMS 0.004, peak 0.018. Wi-Fi source multipliers remain 0.75 RMS and 0.8 peak.

The timing indicates two separate optimization targets. Dedicated ASR may improve fidelity and reduce model time, while streaming endpointing or stable-prefix decoding is needed to remove most of the roughly one-second final-silence delay.

## Candidate architecture

Use a fast dedicated ASR path for speech and preserve a raw-audio language-model path for sound/event understanding and ambiguous cases. This avoids paying general multimodal reasoning cost before obtaining a transcript while retaining information such as speaker count, tone, alarms, impacts, machinery, and music that plain ASR discards.

## Evaluation protocol

1. Preserve raw physical microphone buffers before runtime cleanup.
2. Score exact normalized match, WER, CER, first-word retention, and correct-prefix length.
3. Measure model load, first inference, and at least three warm inferences independently.
4. Add diverse unseen physical cases: ordinary commands, names, numbers, tool requests, corrections, overlapping speech, room noise, and non-speech events.
5. Test repeated acoustic retransmission only as a degradation stress test; never use the prior transcript as the next lane's hidden input.
6. For semantic models, score intent/answer/tool selection from a blind scenario key. A tool call that is not requested counts as a failure.
7. Retest finalists live at frozen loudness, then measure sound onset to response onset rather than only API time.

### Physical corpus expansion: unseen complex sentence

Reference: “At seven forty-three, Mira placed two cobalt notebooks beside the quiet projector because Doctor Chen requested a careful inventory.”

Current Omni transcript: “At seven free, I placed two cobalt whiskers beside the quiet checkster because doctor, Chen requested a careful inventory.”

The initial “At” survived, so this example is not primarily an onset-clipping failure. It tests number phrases, a proper name, uncommon adjective–noun combinations, and a subordinate clause. The exact raw Wi-Fi-camera microphone buffer is preserved for all candidates.

Three repeated offline calls on that identical file produced WER 25%, 30%, and 25%. One run changed “whiskers” to “whisk” and “checkster” to “shester” despite temperature zero. Accuracy and repeatability are therefore tracked separately; a lower average WER is insufficient if the same acoustic evidence yields unstable text.

## Live process-flow requirement

Every deployed change must appear as an actual component in the lane process-flow diagram. The target live flow is:

`physical microphone -> capture/resample -> waveform gate -> neural VAD/endpointing -> fast ASR -> raw-audio environment interpreter (when invoked) -> AI-only dialog/intent/tool decision -> tool execution (when selected) -> response model -> TTS -> physical speaker`

The cards must derive model names, active/benchmark mode, state, and measured latency from runtime payloads. A candidate being tested must be labeled as a benchmark candidate; it must not be shown as production-active until it is wired into the live lane path.

## Issues found while establishing baseline

- Tool-routing false positive: the agent treated “Telephone test. Say exactly: she sells sea shells on the sea shore.” as a request to capture sea shells and invoked `current_snapshot`. This becomes a negative tool-choice regression case.
- A later 3.5-second low-level buffer passed the energy/VAD gate but contained no clear speech according to Omni. This is retained as a false-positive/no-speech case.
- Total reaction latency is currently dominated more by endpointing plus response decision than by the raw transcription call.

## Reproduction

The benchmark prints one JSON record per inference and writes the same records as a JSON array. The model adapter receives only the audio path and task instruction; reference text, tags, case identity, and expected intent are never exposed to inference.

Phi-4 is launched with its official speech and vision LoRAs exposed as local vLLM model names `speech` and `vision`. The optimized benchmark profile uses the original 4K working context and a 50% memory reservation because short interactive audio does not need the checkpoint's full 128K context; this avoids LongRoPE short-sequence degradation and leaves more unified memory for the rest of the live system.

Launch note: Microsoft’s model-card command includes `--lora-extra-vocab-size=0`, but installed vLLM 0.20 has removed that legacy option. The local profile omits it while retaining the required rank-320 speech and vision adapters.

### Phi-4 first local result

Phi-4 Multimodal loaded successfully on the GB10 through local vLLM 0.20 in BF16. Model weights consumed about 10.55 GiB; the 50% memory profile left roughly 44 GiB system memory available after startup. Loading weights took 48.9 seconds and one-time engine compile/warmup took another 49.0 seconds.

The official speech LoRA did not outperform the existing Omni model on this physical corpus. It returned “She saw seashells on the seashore” for the tongue twister and reduced the complex sentence to variants such as “At 7:03, place two cobalt discs beside the acquired text, as requested by Gen.” It also hallucinated Chinese text on every repetition of the no-clear-speech buffer. This disqualifies it as the direct ASR hot path. It remains under evaluation for audio-event and spoken-query reasoning behind VAD and dedicated ASR.

Scorer correction: the first result parser discarded non-Latin characters during normalization, which could make a Chinese hallucination look like empty output. Normalization is now Unicode-alphanumeric, and no-speech cases are scored from raw non-whitespace output before token normalization.

### Dedicated-ASR observations

Parakeet V2 and V3 both execute short physical utterances in roughly 50–80 milliseconds after model warmup and return empty output for the low-level control. V2 is more accurate than multilingual V3 on the complex English sentence and is therefore the current fast-path leader. Whisper large-v3-turbo is slower and hallucinates on the no-speech control without improving either scored speech case.

Across Nemotron Omni, Phi-4, Parakeet V2/V3, and Whisper Turbo, the tongue-twister recording consistently yields “saw,” “sold,” or “follows” rather than “sells.” Agreement across unrelated model families is evidence that the physical capture itself is acoustically ambiguous at that word. The solution must include better capture/endpoint evidence and calibrated uncertainty, not a deterministic lexical repair.

Canary 1B Flash is the best authoritative recognizer so far: it improves the complex sentence to 20% WER, remains deterministic across repetitions, and rejects the no-clear-speech buffer. Parakeet V2 remains the best low-latency first hypothesis. The deployment target is Canary authority plus Parakeet early telemetry, with no phrase-specific voting or correction.

### Resource correction for simultaneous serving

The original Omni service reserved 80% of unified memory for eight 131K-token sequences, leaving only about 3 GiB available even though live voice turns are short. The local profile now defaults to four 32K-token sequences, 58% GPU-memory utilization, and 8K batched tokens. This retains ample dialog context while creating room for a shared dedicated-ASR service. The reduced profile must pass live regression tests before being considered final.

If Canary is empty after the waveform has already passed the lane's energy and MarbleNet gates, the unchanged Parakeet hypothesis is selected as a generic availability fallback. Both raw hypotheses, the selected model, selection reason, and disagreement remain visible.

### Latency and stability iteration

Prior lane replies were removed from the initial transcript-to-decision prompt after a live turn copied an older answer instead of addressing “It’s before dawn.” JSON-constrained decoding and an initial 96-token cap were enabled while retaining the full semantic tool schema. An unseen physical non-tool turn then responded to the current transcript rather than stale history. The later capability-boundary contract required at most 55 tokens across its 28-case benchmark, allowing the live cap to be reduced safely to 64 tokens.

The physical tool request “What is the local time right now?” was transcribed exactly by Canary, selected `current_time` through Nemotron’s model output, executed the live tool, and spoke the returned EDT timestamp. No deterministic intent matcher or controller-authored answer was used. The original post-tool model pass took 2.88 seconds because it reattached audio and supplied 898 consumed tokens. A current-turn evidence prompt now omits redundant audio and old conversation after authoritative ASR. The variant “Tell me the exact local time now” (heard acoustically as “Tell me Zach’s local time now”) still selected the correct tool; post-tool Nemotron latency fell to 0.52 seconds and 604 consumed tokens, an approximately 82% reduction.

Initial MarbleNet rejection now retains waveform-positive onset audio for up to 2.5 seconds of candidate evidence rather than deleting the first short window. On an unseen regression phrase, both ASR models subsequently recovered “Crimson herons cross seven narrow rivers after sunset” exactly, including the first word.

The physical capture cadence was reduced from 0.5 to 0.4 seconds and the final boundary from 0.75 to 0.65 seconds, with all signal thresholds and loudness unchanged. A long sentence containing two comma pauses remained one complete 8.4-second turn. Measured boundary silence improved from 1.20 to 0.98 seconds, about 220 milliseconds. Canary retained the full sentence with substitutions (“Elena” to “Eline” and “every” to “a”), not truncation.

Concurrent Parakeet and Canary execution was benchmarked and rejected. Fifteen repeated calls produced stable transcripts, but the long-clip median increased from 0.321 seconds sequential to about 0.350 seconds concurrent, while short clips were effectively unchanged. Both models contend on the same GPU execution path, so the live service has been restored to sequential execution.

Six newer physical captures were added to the blind corpus, including onset-loss, onset-retention, tool-decision, exact-recovery, and long internal-pause cases. Raw Canary aggregate WER on the expanded speech set is 34.0%, with zero false transcripts on the no-clear-speech control. The high aggregate is driven partly by two historical onset-truncated buffers on which Canary returns empty.

Offline general preprocessing was evaluated without gain or loudness normalization. High-pass filters at 80 and 120 Hz worsened aggregate WER to 35.1%. FFT denoising improved it to 22.3–23.4%. Non-local-means denoising at strength `0.00005` was best at 21.3% and retained zero false speech. However, it regressed the complex inventory clip from 20% to 30% WER and the long internal-pause clip from 11.1% to 16.7%, while an external ffmpeg pass costs a 116 ms warm median. Much of the aggregate gain came from rescuing old onset-truncated buffers now addressed at capture time. Denoising therefore remains benchmark-only rather than adding latency and regressions to every live turn.

BF16 autocast was compared immediately against FP32 with three repetitions of every expanded-corpus clip. Both were stable and preserved the no-speech control. BF16 produced a small word-boundary improvement (aggregate WER 33.0% versus 34.0%) but was slower: 232 ms median request latency versus 221 ms for FP32. FP32 remains live and the experimental precision switch was removed.

The first explicit reverse-direction physical test sent “Obsidian swans pass four silver gates before morning” through the Wi-Fi camera speaker toward the server lane. Talkback completed with a full-scale source waveform, but the server NexiGo microphone remained at RMS 0.00001 and produced no speech candidate. Its input was unmuted at the frozen 70% level. This direction is recorded as an acoustic/hardware-path failure, not an ASR failure or a successful lane bounce; no gain or loudness was changed.

### Model-only decision contract bakeoff

Nemotron's exact live text decision was expanded from a few spot checks to 28 cases: eight self-contained dialog requests and two cases for each of ten tools. The old contract preserved all dialog cases but selected only 7/20 required tools, for 53.6% strict overall accuracy and 0.861-second median latency. A shorter contract fell to 50.0%. Reordering stable instructions before the current transcript raised accuracy to 71.4% but did not improve median latency.

The valid decisions used at most 55 completion tokens. Reducing the cap from 96 to 64 preserved 96.4% accuracy, moved median latency from 0.920 to 0.915 seconds, and reduced p95 from 1.292 to 1.105 seconds. The 64-token cap is now live and exposed in the decision node.

Physical verification covered three routes. A repetition sentence remained no-tool and was echoed. It chooses only `proceed` or `listen`; `listen` suppresses TTS and playback. No phrase matcher, reference transcript, expected intent, or cross-lane content is used. The guard scored 34/34 on its focused benchmark with a 0.276-second median and 0.307-second p95, and parallel execution avoids a new serial latency stage.

### Continuous server capture and first stable reverse utterance

The recovered NexiGo level exposed a second, independent reverse-path defect. Lane 1 requested 0.25-second chunks by launching a new `ffmpeg`/PulseAudio process for every chunk. Boundary artifact timestamps showed starts roughly 0.47–0.52 seconds apart, so approximately 0.22–0.27 seconds of physical sound was never recorded between adjacent windows. This converted the same camera-speaker waveform into different fragments on each pass and made model comparisons misleading.

The server lane now owns one persistent `ffmpeg` PulseAudio reader. It continuously drains `dgx_nexigo_70` as mono 16 kHz PCM and slices exact 0.25-second analysis windows without restarting capture. Live measurements show 0.247–0.249 seconds capture wall time, approximately 0.008 seconds processing gap, one process start, and `dropped_gap_seconds=0.0`. Processing time between windows no longer represents missing audio because PCM remains buffered in the same stream. The live process graph exposes this as a distinct `Continuous Server PCM Reader` component between the supervised microphone adapter and lane-isolated transport.

### Decision-runtime latency alternatives

The local vLLM service already enables automatic prefix caching, but direct metrics showed zero cached prompt tokens after five 468-token requests sharing the same stable contract prefix.
